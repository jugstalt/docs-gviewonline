    Triggers¶

    Cron Trigger¶

    Starts the workflow on a schedule while the workflow is active.

    Inputs: none (starts the workflow) · Outputs: main

    Parameter Type Description
    Cron expression (required)
    expression    		 text When to run: minute hour day month weekday, e.g. 0 7 * * 1-5 is 7:00 on workdays, */15 * * * * every 15 minutes.
    Time zone
    timeZone    		 text Time zone of the schedule, e.g. Europe/Vienna.
    Example: Every workday at 7:00

    While the workflow is active it starts at the given times with one item.

    Parameters:

    {
  "expression": "0 7 * * 1-5",
  "timeZone": "Europe/Vienna"
}

    Output:

    [
  {
    "timestamp": "2026-11-11T06:00:00.0000000+00:00",
    "expression": "0 7 * * 1-5"
  }
]

    Email Trigger¶

    Starts the workflow when unread mails are in a mailbox (IMAP), while the workflow is active. Checks at an interval; one run per check with one item per mail: sender, recipients, subject, date, text, html and the attachments as binary data. After the run has started the mails are marked as read, moved or deleted. Mails that are unread when the workflow is activated count.

    Inputs: none (starts the workflow) · Outputs: main

    Parameter Type Description
    Mail server (required)
    credentialId    		 credential (IMAP Server) The mailbox to watch: an IMAP Server credential.
    Folder
    folder    		 text Mail folder to watch, e.g. INBOX or INBOX/Orders.
    From contains
    fromContains    		 text Only mails from a sender with this text, e.g. @shop.example; empty: all.
    Subject contains
    subjectContains    		 text Only mails with this text in the subject, e.g. Invoice; empty: all.
    After processing
    afterProcessing    		 one of: markAsRead, moveToFolder, delete What happens to a mail once the run has started.
    markAsRead: The mail stays in the folder, marked as read.
    moveToFolder: The mail moves into the target folder, e.g. Done.
    delete: The mail is deleted.
    Default: markAsRead.
    Target folder
    targetFolder    		 text Folder for processed mails, e.g. Done; created if it doesn't exist. Only when After processing is moveToFolder.
    Download attachments
    downloadAttachments    		 true/false Attach the files of the mail to the item as attachment1, attachment2, …. Default: true.
    Max message size (MB)
    maxMessageSizeMb    		 integer A larger mail is reported with its header only (tooLarge) and handled like the others. In Advanced. Default: 25.
    Check every (seconds)
    intervalSeconds    		 integer How often the mailbox is checked. In Advanced. Default: 60.
    Example: Invoices arriving by mail

    One item per unread mail; the PDF is attached as attachment1, e.g. for Write File or the AI node.

    Parameters:

    {
  "folder": "INBOX",
  "subjectContains": "Invoice",
  "afterProcessing": "moveToFolder",
  "targetFolder": "Done"
}

    Output:

    [
  {
    "messageId": "<4711@shop.example>",
    "uid": 4711,
    "folder": "INBOX",
    "from": {
      "name": "Shop",
      "address": "billing@shop.example"
    },
    "to": [
      {
        "name": null,
        "address": "pipe@example.com"
      }
    ],
    "cc": [],
    "subject": "Invoice R-17",
    "date": "2026-11-11T08:00:00.0000000+01:00",
    "text": "Please find the invoice attached.",
    "html": null,
    "attachments": [
      "R-17.pdf"
    ],
    "tooLarge": false,
    "$binary": {
      "attachment1": {
        "fileName": "R-17.pdf",
        "mimeType": "application/pdf"
      }
    }
  }
]

    Error Trigger¶

    Starts the workflow when a triggered run of a workflow that uses it as error workflow fails (set on the workflow, its group or the instance). Outputs { workflow, execution, node, subWorkflow, suppressed } of the failed run; execution.url links to it when Pipe:PublicUrl is set.

    Inputs: none (starts the workflow) · Outputs: main

    Parameter Type Description
    Throttle minutes
    throttleMinutes    		 integer Per failed workflow, start at most once in this time; failures in between are counted in 'suppressed' of the next run. 0 reports every failure. Default: 15.
    Example: A run of another workflow failed

    Use it in an error workflow, e.g. to send a mail to the team. node tells which node failed; suppressed counts the failures held back by the throttle.

    Parameters:

    {
  "throttleMinutes": 60
}

    Output:

    [
  {
    "workflow": {
      "id": "import-orders",
      "name": "Import orders"
    },
    "execution": {
      "id": "6f1d0c",
      "mode": "trigger",
      "environment": "PROD",
      "startedAt": "2026-11-11T07:00:00.0000000+00:00",
      "error": "HTTP 503 from https://api.example.com/orders"
    },
    "node": {
      "id": "http",
      "name": "Load orders",
      "error": "HTTP 503 from https://api.example.com/orders"
    },
    "suppressed": 0
  }
]

    Execute Workflow Trigger¶

    Starts the workflow when another workflow calls it with Execute Workflow; outputs the caller's items.

    Inputs: none (starts the workflow) · Outputs: main

    This node has no parameters.

    Example: The items of the caller

    Another workflow calls this one with Execute Workflow; its items arrive here unchanged. The output of the last node goes back to the caller.

    Output:

    [
  {
    "customer": "Anna",
    "open": 120
  }
]

    File Trigger¶

    Starts the workflow when new files appear in a folder released by the host, while the workflow is active. Checks the folder at an interval and reports a file once it is complete. One run per check, with one item per file: folder, path, name, size, modified and event. Files that exist when the workflow is activated are not reported. Read File reads the content.

    Inputs: none (starts the workflow) · Outputs: main

    Parameter Type Description
    Folder (required)
    folder    		 text Which folder to watch: one of the folders the administrator has set up for workflows.
    Path
    path    		 text A subfolder of the folder, e.g. incoming; empty for the folder itself.
    File pattern
    pattern    		 text Which files count, e.g. .csv or order-.xml; * for all.
    Include subfolders
    includeSubfolders    		 true/false Watch the subfolders of the path too. In Advanced. Default: false.
    Events
    events    		 one of: created, createdOrChanged Which files start the workflow.
    created: Only files that weren't there before.
    createdOrChanged: New files, and files whose size or time changed.
    Default: created.
    Check every (seconds)
    intervalSeconds    		 integer A file is reported when it was unchanged in two checks in a row, so it comes after up to two intervals. In Advanced. Default: 10.
    Example: New CSV files in the incoming folder

    One run per check with one item per new file. The file isn't read yet: Read File with {{ $json.path }} reads it.

    Parameters:

    {
  "folder": "files",
  "path": "incoming",
  "pattern": "*.csv",
  "events": "created"
}

    Output:

    [
  {
    "folder": "files",
    "path": "incoming/orders-17.csv",
    "name": "orders-17.csv",
    "size": 2048,
    "modified": "2026-11-11T08:00:00.0000000+00:00",
    "event": "created"
  }
]

    Form Trigger¶

    Starts the workflow from the user portal: declares the form the user fills in and outputs one item with the values. Without a Form Trigger a published workflow starts without input.

    Inputs: none (starts the workflow) · Outputs: main

    Parameter Type Description
    Fields
    fields    		 list of JSON The inputs of the form. Each has a name (the property in the item), a label, a type (text, multiline text, number, boolean, date, choice or password), and optionally a description, a placeholder, a default, a regular expression the text must match as a whole (with the message shown otherwise) and the values of a choice.
    Example: A request form in the portal

    The portal shows the fields; when the user sends the form, the workflow starts with one item of the values, named as the fields.

    Parameters:

    {
  "fields": [
    {
      "name": "customer",
      "label": "Customer",
      "type": "text"
    },
    {
      "name": "amount",
      "label": "Amount",
      "type": "number"
    },
    {
      "name": "urgent",
      "label": "Urgent",
      "type": "boolean"
    }
  ]
}

    Output:

    [
  {
    "customer": "Anna",
    "amount": 120,
    "urgent": true
  }
]

    Manual Trigger¶

    Starts the workflow when it is run from the editor.

    Inputs: none (starts the workflow) · Outputs: main

    This node has no parameters.

    Example: Start from the editor

    Run or Test in the editor starts here with one empty item; the next nodes add the data.

    Output:

    [
  {}
]

    Recovery Trigger¶

    Starts the workflow when a workflow that failed and was reported to this error workflow runs successfully again (triggered runs only). Outputs { workflow, execution, failedSince, failedExecution, failures }; execution.url and failedExecution.url link to the runs when Pipe:PublicUrl is set.

    Inputs: none (starts the workflow) · Outputs: main

    This node has no parameters.

    Example: A failing workflow works again

    Use it next to an Error Trigger, e.g. to send an all-clear mail.

    Output:

    [
  {
    "workflow": {
      "id": "import-orders",
      "name": "Import orders"
    },
    "execution": {
      "id": "8a2e41"
    },
    "failedSince": "2026-11-11T07:00:00.0000000+00:00",
    "failedExecution": {
      "id": "6f1d0c"
    },
    "failures": 3
  }
]

    Webhook Trigger¶

    Starts the workflow when its URL is called while the workflow is active.

    Inputs: none (starts the workflow) · Outputs: main

    Parameter Type Description
    Path (required)
    path    		 text Last part of the URL: the workflow is called at /webhook/<path>, e.g. orders/new; unique across active workflows.
    HTTP method
    method    		 one of: any, get, post, put, patch, delete Which calls start the workflow.
    any: Every method.
    get: Calls without a body, e.g. from a link.
    post: Calls with a body, e.g. forms and other systems; the usual choice.
    put: PUT calls.
    patch: PATCH calls.
    delete: DELETE calls.
    Default: post.
    Respond
    responseMode    		 one of: immediately, whenFinished, usingRespondNode When and with what the caller gets an answer.
    immediately: Answer 202 with the execution id at once; the workflow runs in the background.
    whenFinished: Wait for the run and answer with the items of the last node.
    usingRespondNode: Wait until a Respond to Webhook node answers.
    Default: immediately.
    Wait timeout (seconds)
    timeoutSeconds    		 integer After this time the caller gets 202 and the run goes on; time in the queue counts, and a run still queued then gets 503 and leaves the queue. Only when Respond is whenFinished or usingRespondNode. In Advanced. Default: 30.
    Credential
    credentialId    		 credential (Basic Auth, Bearer Token, API Key Header) Callers must authenticate with it; without one the webhook is public.
    Example: Receive an order from a shop

    The shop sends POST /webhook/orders/new with JSON; the item holds method, path, query, headers, body and the time. Uploaded files arrive as attachments.

    Parameters:

    {
  "path": "orders/new",
  "method": "post",
  "responseMode": "immediately"
}

    Output:

    [
  {
    "method": "POST",
    "path": "orders/new",
    "query": {},
    "headers": {
      "Content-Type": "application/json"
    },
    "body": {
      "id": 17,
      "customer": "Anna",
      "amount": 120
    },
    "receivedAt": "2026-11-11T08:00:00.0000000+00:00"
  }
]
